# handoff 2026-08-29

Next up is **har-gdz** — make opencode actually load the harness. Its description
carries what was verified against the installed binary, not guessed; read it
before designing anything, because two obvious moves are traps.

## Start here: har-gdz, then ccp-veh

The goal driving all of this: control-center-pro should become usable from
opencode. That needs har-gdz here first, then ccp-veh applied there, so
`template/AGENTS.md` arrives *by install* rather than being hand-written in ccp
and diverging from the template on day one. Doing ccp-veh first means writing
the opencode config twice.

Three things verified by running the binary, all in har-gdz:

- opencode **already** discovers project `.claude/skills/` — no symlink needed,
  don't add one.
- opencode does **not** read `.claude/agents/`, and symlinking it is worse than
  nothing: the frontmatter loads but `model: haiku` parses as *provider* `haiku`
  with an empty model id, and the comma-string `tools:` resolves to invalid. It
  fails at spawn, not at load. Generate both dialects from one body (har-wkr).
- opencode has **no** session-start hook that can inject context. Don't build the
  plugin. Use the declarative `instructions` key in `opencode.json` instead, and
  keep AGENTS.md's "run `scripts/brief.sh` yourself" line for the dynamic half.

## The thing that keeps biting

**bd writes into every instruction file it finds, on every run.** `bd init` puts
a block in CLAUDE.md *and* AGENTS.md; `bd setup codex` adds a second to
AGENTS.md. My first fix at har-7xv created the duplication it was removing, and
the check I'd written looked only at CLAUDE.md so it reported clean — the exact
shape of the bug it was built to catch. The correctness reviewer found it by
running the installer. Assume any new bd-adjacent step needs an end-to-end
install run, not a reading.

Do **not** run `bd setup opencode`. It creates no `.opencode/` files, never says
the word "opencode", and appends a 128-line duplicate of guidance AGENTS.md
already has. There is no opencode integration in bd to hook into yet — worth
re-checking on a bd upgrade.

  wires neither git transport for the ledger.
- **har-rew** (P1) is the sharpest of the new ones. A local reviewer handed an
  oversized packet silently reads the first few thousand tokens and passes.
  `OLLAMA_CONTEXT_LENGTH` is unset; `qwen3.8:27b`'s advertised 262144 is the
  architecture max, not the allocation. `review.sh` must refuse, not warn.
- `claude -p` is off-*context*, not off-account — same quota, and the child
  inherits `.claude/settings.json` so SessionStart hooks fire per spawn.
- A second session was committing here while I worked (a89d0ce, e036fa4). Stage
  your own files explicitly; `git add -A` will sweep up someone else's work.
